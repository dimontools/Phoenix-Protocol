# 🔥 Phoenix Codec (Кодекс Феникс)

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/drive/1S6DNgPe6Chqtrn1QVrrJhx8BiVWbzV22?usp=sharing)

**Экспериментальный мультимедийный кодек для экстремально низких битрейтов и плохих каналов связи.**

[English version](README_EN.md)

«Феникс» — это исследовательский проект, который доказывает, что для передачи визуальной и звуковой информации не нужно передавать каждый пиксель или сэмпл. Достаточно передать «слепок сути» (латентное представление), а на приемнике восстановить его с помощью нейросети.

Проект вдохновлен идеей семантического сжатия, устойчивости к шуму и передачи смысла вместо данных.

## ✨ Ключевые особенности

*   **Видео-сжатие:** Передача узнаваемого лица занимает всего **~3 КБ** на кадр (в 4 раза меньше JPEG-90).
*   **Аудио-сжатие:** Передача разборчивой речи занимает **~1.5 kbps** (в 10-20 раз меньше стандартных аудиокодеков). Голос становится «роботизированным», но смысл сохраняется.
*   **Устойчивость к шуму:** Использование «ключа» (семени генератора псевдослучайных чисел) позволяет восстановить кадр даже после прохождения через очень шумный канал.
*   **Сохранение пропорций:** Видео-кодек автоматически делает паддинг и обрезку, чтобы сохранить исходный размер и форму кадра.

## 📊 Результаты тестов

*   **Видео:** Сжатие фото 256x256 до **3.7 КБ** (вместо 57 КБ исходного JPEG). Качество: узнаваемое, слегка «мыльное», но с сохранением эмоций.
*   **Аудио:** Сжатие 3 секунд речи до **900 байт** при битрейте 1.5 kbps. Слова разборчивы, интонация сохраняется.
*   **Видеозвонок:** Работающий прототип (видео + аудио) с задержкой около 1 секунды и легким эхом (решается буферизацией и наушниками).

### 📊 Сравнение с классическими и нейросетевыми кодеками

Тест на реальном фото (256x256, лицо). PSNR — метрика пиксельной точности (чем выше, тем лучше), но Феникс оптимизирован для **семантической узнаваемости**, а не для пиксельного совпадения.

| Метод | Размер (байт) | PSNR (dB) | Комментарий |
| :--- | :--- | :--- | :--- |
| **Cheng2020 (Q=6)** | 2712 | 40.00 | Лучший нейрокодек (максимальный PSNR) |
| **MBT2018 (Q=6)** | 3136 | 39.80 | Передовой нейрокодек |
| **JPEG (Q=20)** | 3732 | 32.01 | Классика, но «каша» |
| **Феникс (Hyperprior Q=6)** | **3744** | **39.47** | **Наш подход: смысл, а не пиксели** |
| **AVIF (Q=80)** | 8123 | 41.76 | Лучший PSNR, но тяжелый |
| **JPEG (Q=90)** | 14250 | 40.44 | Классика, но огромный |

**Вывод:** Феникс в 3.8 раза меньше JPEG-90 и в 2.2 раза меньше AVIF. Он проигрывает топовым нейрокодекам (Cheng2020) по PSNR, но **выигрывает в устойчивости к шуму** (что доказано в `phoenix_space.py`) и **работает на 500 байтах** (Quality=1), где классика рассыпается.

## 🛠 Как это работает (Кратко)

1.  **Видео:** Кадр проходит через нейросетевой энкодер (CompressAI / Hyperprior) и превращается в компактный латент.
2.  **Аудио:** Звук проходит через нейросетевой кодек (EnCodec) и превращается в компактные «коды».
3.  **Передача:** Данные передаются по каналу. Мы имитируем шум, который искажает сигнал.
4.  **Восстановление:** Приемник использует «семя» (4 байта) для генерации того же шума и вычитает его. Декодер восстанавливает видео и аудио.

### 📂 Структура проекта
- `core/phoenix_cli.py` — CLI-утилита для сжатия/восстановления видео.
- `core/phoenix_call.py` — прототип видеозвонка (видео + аудио в реальном времени).
- `core/phoenix_audio.py` — аудио-кодек на базе EnCodec.
- `core/phoenix_space.py` — симуляция космического канала с потерями пакетов.

### ⚠️ Известные проблемы
- **Эхо и задержка:** В прототипе видеозвонка наблюдается эхо и задержка ~1 сек. Требуется интеграция AEC (Acoustic Echo Cancellation).
- **Разрешение:** Видео-кодек работает с латентами 256x256. Для 4K используется паддинг, что может снижать детализацию.
- **Аудио:** При битрейте 1.5 kbps речь разборчива, но имеет «роботизированный» тембр.

## ⚠️ Честные ограничения (Honest Limitations)

Мы хотим быть прозрачными. «Феникс» — это **исследовательский протокол**, а не готовый продукт. Вот его ключевые ограничения:

1.  **Зависимость от моделей:** Для декодирования требуется предварительно установить модели CompressAI (Hyperprior) и EnCodec. Их размер (~50 МБ) не входит в заявленный битрейт, но должен быть на приемнике.
2.  **Механизм «семени» (Главное ограничение):** Восстановление шума по seed работает, если профиль шума **известен и детерминирован** (например, при передаче по каналу с предсказуемыми помехами или при использовании согласованного ключа). 
    *   **Для случайного шума** (как в реальных радиоканалах) этот метод **не работает**. Эксперименты с генеративным денойзером (Stable Diffusion) показали, что универсальные модели не справляются с сильным случайным шумом в латенте (они начинают «галлюцинировать» текстуры вместо восстановления объекта). Для реальных каналов требуется **специально обученный денойзер** (U-Net), который выходит за рамки текущего MVP.
3.  **Разрешение:** Кодек работает с латентами 256×256. Для 4K используется паддинг, что может снижать детализацию. Это ограничение архитектуры, а не «фича».
4.  **Задержка и эхо:** Прототип видеозвонка (`phoenix_call.py`) имеет задержку ~1 секунду и эхо. Требуется интеграция AEC (Acoustic Echo Cancellation).
5.  **Не production-ready:** Проект не проходил тесты на реальных каналах с BER (Bit Error Rate). Все результаты получены на синтетических симуляциях.

## 🚀 Как запустить (Для разработчиков)

Требуется Python 3.10+ и библиотеки `torch`, `compressai`, `encodec`, `opencv-python`, `sounddevice`.

1.  Установите зависимости:
    ```bash
    pip install -r requirements.txt

2.  Для теста видео: Поместите видео в папку core/ и запустите python phoenix_cli.py --input input_video.mp4 --output result.mp4 --quality 6.

3.  Для теста видеозвонка: Запустите python core/phoenix_call.py. (Убедитесь, что индексы микрофона и динамиков в коде совпадают с вашими).
